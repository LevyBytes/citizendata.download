Privacy Policy

Effective November 19, 2026

CitizenData, developed by LevyBytes, lets you review and save account records locally. There is no server that receives your data: account files and backups are processed on your device and are not uploaded to the developer or to anyone else.

Account data and local processing

A file you choose may contain your player identity, pledges, buybacks, account balances, billing and subscription records, Hangar Log entries, referrals, organization memberships, and related image URLs. The dashboard reads that file in browser memory to display it and create exports you request. It has no account-data upload service or hosted account database.

The packaged example account and images are presentation data, including selected public citizen profiles. Example referral placement does not represent a real referral relationship. Your loaded file is separate from those examples.

Browser extension and permissions

The extension reads your account, and optionally the member rosters of organizations you choose, only when you start a build from the dashboard. It makes read only requests to a fixed list of RSI pages while you are signed in to RSI in the same browser: your dossier, balances, billing and subscription history, Hangar Log, current Hangar, buy-back list, the page of each buy-back for its price and contents, referrals, and organization memberships. The image workflow runs in the dashboard from the image links already present in the loaded account file and does not require an RSI sign in.

The extension asks Chrome for five permissions: storage and alarms to keep and continue a build, unlimited storage so that Chrome does not clear what the extension keeps when the disk runs low, an offscreen page to read the pages it fetched, and cookies. It uses the cookies permission for one purpose: RSI's own account requests need RSI's session token, and the extension reads that token from the browser for each request that needs it and sends it only to RSI. The token is read transiently, never stored: it is not written into the account JSON, dashboard messages, logs, or extension storage. CitizenData does not collect passwords or MFA values and does not provide account purchase, reclaim, gift, buyback, or upgrade actions. Account login remains with RSI.

Storage, retention, and deletion

The dashboard keeps the loaded account model in memory. Closing or reloading the page discards that model; it does not delete the original file. While Build history is on in the extension, the dashboard asks the extension for your latest finished build when it loads and opens it in place of the example; with Build history off it is given nothing until you build. While Build history is on, a complete account file you open with Load JSON is also handed to the extension, which keeps it as the latest build of that account when it holds none, or an older one; an Orgs JSON you open afterwards adds its rosters to that build. Neither goes anywhere else. A small browser session-storage value chooses the decorative hero artwork and contains no account records. Every finished build is saved to your device as a file; that file is yours to keep, move, or delete.

The extension keeps its records in its own storage in your browser profile and nowhere else. It keeps the latest finished build of each account, which later builds compare against; while a build runs, the pages it has fetched, which are deleted once the dashboard confirms the file was saved; and records of its jobs, run authorizations, and the local dashboards you allowed. Earlier builds are kept while Build history is on in the extension popup. It is on unless you turn it off. While it is on, a build that differs from the one before keeps the earlier one, compressed, up to the number you choose; each kept build can be saved as a file or deleted in the popup. While Build history is on, the organization member rosters you collected are also kept as one Orgs JSON, replaced when a later build carries different rosters; it can be saved or deleted in the popup in the same way. While Build history is on, the images the dashboard downloads are also kept, so the dashboard can show them again without the Images ZIP; the dashboard downloads them, the extension only stores them, and they can be deleted in the popup. With Build history off the extension holds no images. These records hold the same account data and images as your backup files and Images ZIP, and never hold the RSI session token. Exporting a recovery backup copies the working records to a file you choose; it does not remove them.

Clear all local extension data in the extension popup removes everything the extension keeps, including kept builds. Removing the extension removes its storage as well, and Chrome can clear it if the device runs very low on disk space. Clear site data to remove the site's browser storage. Files you have downloaded, browser or operating-system backups, and copies you shared must be deleted separately. The developer cannot remotely access, restore, or delete your local files.

Exports and other people's information

Downloads are created only when you request them. You choose which supported sections to export and whether to share the resulting file with another person or tool. CitizenData does not automatically upload, email, sell, or synchronize those exports.

Billing records, referral lists, and organization rosters can contain personal information about you or other people. Protect these files and share only information you are entitled to disclose. Redacted or unavailable identities are not revealed by the tool. A third-party tool that receives a file you share handles it under its own policy.

Images, links, and website hosting

The dashboard uses bundled local example images, local media from a supported image package, and, when Build history is on in the extension, the images the extension keeps from an earlier download. It does not automatically load remote account images just because their URLs appear in a loaded file. When you explicitly start an offline image download, the dashboard contacts only RSI's two image hosts, robertsspaceindustries.com and media.robertsspaceindustries.com, with browser credentials and referrer information omitted. Those hosts can still receive your IP address and ordinary request information. Other hosts, invalid image bytes, and oversized files are rejected, and a cancelled run does not save a partial ZIP.

Visiting the hosted website sends normal web requests to its hosting providers. The site is served by GitHub Pages through Cloudflare, and both receive your IP address and ordinary request information as any web host does. GitHub states that GitHub Pages logs visitors' IP addresses for security purposes; see GitHub's Privacy Statement and Cloudflare's Privacy Policy. The developer does not add analytics, advertising trackers, tracking cookies, or telemetry to the dashboard or the extension, and has no access to your cookies or your account data. Hosting requests do not include the account file you open locally. A copy of the dashboard opened from your own disk makes no request to the hosted site.

Following links to RSI, Spectrum, GitHub, a wiki, or another community service leaves CitizenData and makes a request to that service. Some example links contain the developer's RSI referral code. Those services apply their own privacy practices.

Support and privacy requests

If you contact the developer, the messages and information you choose to provide are processed through that communication service to respond to you. GitHub issue reports are public. Do not post account backups, billing details, credentials, or personal information there. For a privacy question or request, message the developer on RSI Spectrum; Spectrum's own privacy policy applies to that conversation.

Depending on the law that applies to you, you may have rights concerning personal information provided in support communications. You can use the contact above to make a request. The developer cannot retrieve account data that remains only on your device. No account data is sold or shared for targeted advertising.

Children and policy changes

CitizenData is not directed to children and must be used consistently with RSI's eligibility rules. Do not provide children's personal information through support channels. If you believe such information was provided, contact the developer.

Material changes to collection, permissions, storage, or sharing will be reflected in this policy before the changed feature is released, with any notice or consent required by law. The effective date identifies the current version.
